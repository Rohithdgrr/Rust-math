Why MathVerse

One workspace, thirty-one focused crates

MathVerse splits mathematics into small, composable crates so you depend on only what you need — while the prelude lets you pull the whole library with a single import.

M

Modular by design

31 focused crates under one namespace. Add mathverse-linear-algebra alone, or everything behind mathverse-prelude.

P

Engineered precision

High-precision constants and an explicit error taxonomy give you predictable numerics instead of silent NaN propagation.

E

Embedded-ready

Core crates run no_std with libm support where it matters — MCUs and WASM included.

E

Example-rich

Every crate ships a runnable example. Try cargo run --example <name> --release from the workspace.

Features

Capabilities, in code

Six of the core domains, shown as real working patterns. Every snippet compiles against the MathVerse API surface.

linalg.rs
use mathverse_linear_algebra::{Matrix, Svd};

fn main() {
    let a = Matrix::from_rows(vec![
        vec![3.0, -2.0, 1.0],
        vec![0.5,  7.0, -4.0],
        vec![2.0,  1.0,  9.0],
    ]);

    let inv = a.inverse().expect("matrix is invertible");
    let x = inv * Matrix::column(vec![4.0, 3.0, 1.0]);
    println!("solution: {x}");

    let svd = Svd::of(&a);
    println!("singular values: {:?}", svd.singular_values());
}

Matrix inverse, solve, and singular value decomposition via mathverse-linear-algebra.

calculus.rs
use mathverse_calculus::{derivative, integrate};

fn f(x: f64) -> f64 {
    x.sin() * x.exp()
}

fn main() {
    let df = derivative::central(&f, 0.5, 1e-8);
    println!("f'(0.5) ~= {df:.8}");

    let area = integrate::simpson(&f, 0.0, 2.0, 1000);
    println!("integral(0, 2) f(x) dx ~= {area:.6}");
}

Central-difference derivatives and Simpson integration from mathverse-calculus.

ode.rs
use mathverse_numerical::ode::Rk45;

fn main() {
    // y' = y - t^2 + 1, y(0) = 0.5  (classic RK45 test problem)
    let sol = Rk45::new(0.0, 0.5, |t, y| y - t * t + 1.0)
        .step(0.1)
        .tolerance(1e-6)
        .solve_until(2.0);

    println!("y(2.0) ~= {:.8}", sol.at(2.0));
}

Adaptive Runge-Kutta 4/5 ODE solving with mathverse-numerical.

use mathverse_ai::{tensor::Tensor, nn::Linear};

fn main() {

    let x = Tensor::randn(&[32, 784]);

    println!("out shape: {}", out.shape());   // [32, 128]
}

Tensor operations and neural-network layers from mathverse-ai.

symbolic.rs
use mathverse_symbolic::{Expr, sym};

fn main() {
    let x = sym("x");
    let f = (x.clone().powi(3) + x * 2 - 1) / x.clone().exp();
    let df = f.differentiate(&x).simplify();

    println!("f(x)  = {f}");
    println!("f'(x) = {df}");   // printed as LaTeX
}

Symbolic differentiation, simplification, and LaTeX output from mathverse-symbolic.

fft.rs
use mathverse_transforms::fft;

fn main() {
    let n = 1024;
    let signal: Vec = (0..n)
        .map(|i| (2.0 * std::f64::consts::PI * 50.0 * i as f64 / n as f64).sin())
        .collect();

    let spectrum = fft::rfft(&signal);
    let peak = spectrum.argmax();
    println!("dominant bin: {peak}");   // -> 50 Hz tone
}

Real FFT and peak detection with mathverse-transforms.

Installation

Three ways to add MathVerse

Add the umbrella crate for everything, add a single domain crate for a lean dependency tree, or run the shipped examples directly from the workspace.

1. Everything

Pulls in the full library and re-exports every module through mathverse-prelude. Best for prototyping and REPL-style exploration.

cargo add mathverse

2. Individual crates

Each domain crate stands alone. The workspace has no binary crates — all features are library APIs, so the crate you add is exactly what you compile.

cargo add mathverse-linear-algebra
cargo add mathverse-symbolic

3. Run the examples

Every crate ships runnable examples under crates/mathverse-*/examples. Build them optimized for a real feel of the API.

cargo run --example <name> --release

MSRV: MathVerse requires Rust 1.87 or newer (workspace rust-version). Most crates also compile no_std with libm where applicable.
